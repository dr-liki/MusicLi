# Presentation ViewModels & State Holders

## Overview
Houses all Hilt `@HiltViewModel` classes, `@Singleton`/`@ViewModelScoped` state holders, and UI state models under `presentation.viewmodel` (plus the child `exts` package for `DeckController`). `PlayerViewModel` and `SettingsViewModel` act as primary coordinators delegating to specialized state holders (`PlaybackStateHolder`, `LibraryStateHolder`, `ThemeStateHolder`, `LyricsStateHolder`, `QueueStateHolder`, `DailyMixStateHolder`, `SmartMixStateHolder`, `ConnectivityStateHolder`, `AudioOutputStateHolder`, `SleepTimerStateHolder`, `SearchStateHolder`, `FileExplorerStateHolder`, `MetadataEditStateHolder`, `ListeningStatsTracker`, `MultiSelectionStateHolder`, `PlaylistSelectionStateHolder`, and undo/navigation/removal holders), alongside dedicated screen ViewModels (`PlaylistViewModel`, `ExploreViewModel`, `EqualizerViewModel`, `SetupViewModel`, `MainViewModel`, `AccountsViewModel`, `StatsViewModel`, `RecapViewModel`, `RecapEntryViewModel`, `DeviceCapabilitiesViewModel`, `SongInfoBottomSheetViewModel`, `MashupViewModel`, etc.).

## Interface

### Subdirectories
- `exts`: [./exts/README.md](./exts/README.md) - `DeckController` wrapping an audio-only `ExoPlayer` for dual-deck mashup playback.

### Core Player, Queue, Playback & Sheet State
- `[PlayerViewModel.kt:PlayerViewModel]`, `[PlayerViewModel.kt:PlaybackAudioMetadata]`, `[PlayerViewModel.kt:LocateScrollRequest]`, `[PlayerViewModel.kt:ExploreArtistNavigationRequest]`, `[PlayerViewModel.kt:FullPlayerSlice]`, `[PlayerViewModel.kt:PlayerConfigSlice]`, `[PlayerViewModel.kt:PALETTE_NEIGHBOR_PRELOAD_DEBOUNCE_MS]`, `[PlayerViewModel.kt:withRepositoryHydration]`, `[PlayerViewModel.kt:areEquivalentArtworkUrisForSong]`, `[PlayerViewModel.kt:improvesLyricsLookupComparedTo]`, `[PlayerViewModel.kt:parsePersistedLyrics]`: Central `@HiltViewModel` coordinating MediaController transport, queue building/reordering/shuffling, album/artist/genre/favorite/external-URI/streaming-artist navigation, single & batch metadata/genre/lyrics editing with Android R+ MediaStore permissions, device deletion, sleep timers, discover albums, and sheet/navigation state.
- `[SharedPlayerViewModel.kt:sharedPlayerViewModel]`: `@Composable fun sharedPlayerViewModel(): PlayerViewModel` resolving `PlayerViewModel` against the enclosing `ComponentActivity`.
- `[PlaybackStateHolder.kt:PlaybackStateHolder]`: `@Singleton` managing `mediaController`, `stablePlayerState`, `currentPosition`, progress polling, duration/position reconciliation, play/pause/seek/next/previous/repeat, and shuffle queue mutation.
- `[StablePlayerState.kt:StablePlayerState]`: `@Immutable` snapshot of active song, playback/buffering flags, duration, shuffle/repeat state, and lyrics.
- `[PlayerUiState.kt:PlayerUiState]`: `@Immutable` UI state for playback queue, search results/history, music folders, sort options, storage filters, and undo bars.
- `[PlayerSheetState.kt:PlayerSheetState]`: `enum class { COLLAPSED, EXPANDED }`.
- `[QueueStateHolder.kt:QueueStateHolder]`: `@Singleton` storing `originalQueueOrder` / `originalQueuePlaylistIds` and `prepareShuffledQueueSuspending`.
- `[QueueUndoStateHolder.kt:QueueUndoStateHolder]`: `@ViewModelScoped` timed undo (`4000` ms) for queue item removal (`removeSongFromQueue`, `undoRemoveSongFromQueue`, `hideQueueItemUndoBar`, `onCleared`).
- `[PlaylistDismissUndoStateHolder.kt:PlaylistDismissUndoStateHolder]`: `@ViewModelScoped` queue dismissal and playback restoration (`dismissPlaylistAndShowUndo`, `observeUndoStateAgainstPlayback`, `undoDismissPlaylist`, `hideDismissUndoBar`, `onCleared`).
- `[ExternalMediaStateHolder.kt:ExternalMediaStateHolder]`, `[ExternalMediaStateHolder.kt:ExternalSongLoadResult]`: Resolves external `content://`/`file://` URIs via MediaStore and `AudioMetadataReader`, caches audio/artwork, and builds folder continuation queues (`buildExternalSongFromUri`, `buildExternalQueue`).
- `[SleepTimerStateHolder.kt:SleepTimerStateHolder]`: `@Singleton` mirroring `SleepTimerSession` (`isEndOfTrackTimerActive`, `activeTimerValueDisplay`, `activeTimerDurationMinutes`, `playCount`) and sending sleep-timer/counted-play commands via `MediaController`.
- `[AudioOutputStateHolder.kt:AudioOutputStateHolder]`, `[AudioOutputStateHolder.kt:AudioOutputDevice]`, `[AudioOutputStateHolder.kt:AudioOutputKind]`, `[AudioOutputViewModel.kt:AudioOutputViewModel]`: `@Singleton` and `@HiltViewModel` enumerating audio sink routes and setting preferred playback devices on `DualPlayerEngine`.
- `[ConnectivityStateHolder.kt:ConnectivityStateHolder]`, `[ConnectivityStateHolder.kt:BluetoothAudioDeviceState]`: `@Singleton` tracking validated online status, WiFi state/SSID, and Bluetooth audio devices/battery levels.
- `[OwnerStack.kt:OwnerStack]`: `internal class OwnerStack<B : Any>` tracking live `CoroutineScope` owner bindings across `Activity`/`ViewModel` lifecycles.

### Library, Search, Folders, Mixes, Playlists & Selection
- `[LibraryStateHolder.kt:LibraryStateHolder]`, `[LibraryStateHolder.kt:LibraryGenresState]`, `[LibraryStateHolder.kt:sortGenresList]`, `[LibraryStateHolder.kt:UNKNOWN_GENRE_ID]`: `@Singleton` managing library `StateFlow`s, PagingData flows, sorting, storage filtering, and `trimMemory`/`restoreAfterTrimIfNeeded`.

- `[PlaylistSelectionStateHolder.kt:PlaylistSelectionStateHolder]`: `@Singleton` ordered playlist multi-selection state.

- `[PlaylistViewModel.kt:PlaylistViewModel]`, `[PlaylistViewModel.kt:PlaylistUiState]`, `[PlaylistViewModel.kt:PlaylistSongsOrderMode]`: `@HiltViewModel` managing playlist CRUD, smart playlists, folder pseudo-playlists, sorting/reordering, cover cropping/storage, M3U import/export, merging, and ZIP/M3U sharing (`FOLDER_PLAYLIST_PREFIX`, `sanitizeFileName`).
- `[M3uSyncViewModel.kt:M3uSyncViewModel]`: `@HiltViewModel` configuring and triggering `M3uSyncRepository` folder sync (`selectFolder`, `syncNow`, `disable`).
- `[DailyMixStateHolder.kt:DailyMixStateHolder]`, `[DailyMixStateHolder.kt:isDifferentDay]`: `@Singleton` generating, persisting, and rolling over `dailyMixSongs` and `yourMixSongs`.
- `[SmartMixStateHolder.kt:SmartMixStateHolder]`, `[SmartMixStateHolder.kt:SmartMixTarget]`, `[SmartMixViewModel.kt:SmartMixViewModel]`, `[MixPreview.kt:MixPreview]`: `@Singleton` and `@HiltViewModel` generating AI/smart mixes, managing previews, saving playlists, and undoing daily mix replacements.

## Invariants
- `[OwnerStack.kt:OwnerStack]`, `[SharedPlayerViewModel.kt:sharedPlayerViewModel]`, `[PlaybackStateHolder.kt:onCleared]`, `[LibraryStateHolder.kt:onCleared]`, `[DailyMixStateHolder.kt:owners]`, `[ThemeStateHolder.kt:owners]`, `[SearchStateHolder.kt:onCleared]`, `[SleepTimerStateHolder.kt:onCleared]`, `[LyricsStateHolder.kt:initialize]`, `[ConnectivityStateHolder.kt:initialize]`: Singleton state holders are shared across `Activity`/`NavBackStackEntry` lifecycles via `OwnerStack<CoroutineScope>`; clearing an older owner never tears down a newer active owner's scopes/collectors, and `ConnectivityStateHolder` tears down system callbacks only when `owners.isEmpty`.
- `[PlayerViewModel.kt:launchLatestFullQueuePlayback]`, `[PlayerViewModel.kt:beginDirectPlaybackRequest]`, `[PlayerViewModel.kt:attachPreparedQueueSegmentsIfCurrent]`: Full-queue and direct playback requests use monotonic request tokens to cancel/drop stale builds; batch queue attachment checks `player.currentMediaItem?.mediaId == startSongId && player.mediaItemCount == 1` and appends in batches of `200`.
- `[PlayerViewModel.kt:onWritePermissionResult]`, `[PlayerViewModel.kt:dispatchWritePermissionResult]`, `[PlayerViewModel.kt:offerToRestoreInterruptedSaves]`, `[PlayerViewModel.kt:deleteSelectedFromDevice]`: Android R+ MediaStore write/delete flows queue pending requests, process at most one write request per callback in fixed priority order, exclude the currently playing song from deletion, and increment `answeredWriteRequests` in `finally`.
- `[PlaybackStateHolder.kt:replacePlayerQueuePreservingCurrent]`, `[PlaybackStateHolder.kt:toggleShuffle]`, `[PlaybackStateHolder.kt:reorderQueueInPlace]`: Queue mutations operate on `MediaController` (never bypassing it via `DualPlayerEngine.masterPlayer`) to keep timelines synchronized; `toggleShuffle` enforces `400` ms cooldown and switches to bulk replacement at `BULK_REPLACE_THRESHOLD = 80`.
- `[SettingsViewModel.kt:toggleDirectoryAllowed]`, `[SettingsViewModel.kt:applyPendingDirectoryRuleChanges]`, `[SettingsViewModel.kt:onCleared]`, `[SetupViewModel.kt:applyPendingDirectoryRuleChanges]`: Directory rule writes run on `@AppScope` so navigating back does not cancel pending DataStore updates, and `onCleared()` flushes pending sync refreshes before destruction.
- `[SettingsViewModel.kt:supportedOrDefault]`, `[SettingsViewModel.kt:toggleLyricsProvider]`, `[SettingsViewModel.kt:exportAppData]`, `[SettingsViewModel.kt:restoreFromPlan]`: Unsupported `PCM_FLOAT`/`BIT_PERFECT_USB` audio modes fall back to `SYSTEM_DEFAULT`; at least one lyrics provider remains enabled; backup export/inspect/restore serialize against concurrent transfer/inspection flags.
- `[ListeningStatsTracker.kt:ListeningStatsTracker]`, `[ListeningStatsTracker.kt:finalizeCurrentSession]`: All session mutators are `@Synchronized`; sessions record only when `accumulatedListeningMs >= 5000L`, capping in-memory history at `500` items.
- `[DailyMixStateHolder.kt:dailyMixLock]`, `[DailyMixStateHolder.kt:checkRequested]`, `[SmartMixStateHolder.kt:generate]`, `[SmartMixStateHolder.kt:undoDailyMixUpdate]`: Mix generation checks replacement counters/request IDs to avoid overwriting user-replaced same-day mixes; Smart Mix enforces `1..100` song limits, `4_000L` ms minimum thinking delay, and non-concurrent generation/action guards.
- `[ColorSchemeProcessor.kt:memoryCache]`, `[ColorSchemeProcessor.kt:loadCachedColorScheme]`, `[ThemeStateHolder.kt:individualAlbumColorSchemes]`, `[ThemeStateHolder.kt:trimMemory]`: Caches are bounded (`LruCache(20)` in `ColorSchemeProcessor`, `96` flows in `ThemeStateHolder`), recycle temporary Bitmaps, guard local artwork cache reads with `localArtworkCacheMutex` + generation checks, and purge/set reload flags on memory trim.
- `[EqualizerViewModel.kt:hasLoadedPreferences]`, `[EqualizerViewModel.kt:setBandLevel]`, `[ArtistSettingsViewModel.kt:ArtistSettingsUiState]`, `[ArtistSettingsViewModel.kt:removeDelimiter]`: Equalizer clamps bands (`-15..15`) and effect strengths (`0..1000`), debounces slider writes (`150` ms), and refuses to overwrite prefs on `onCleared` before initial load; artist settings require at least one artist delimiter.
- `[PlaylistViewModel.kt:PlaylistViewModel]`, `[FileExplorerStateHolder.kt:getOrBuildMediaStoreDirectoryIndex]`, `[StatsViewModel.kt:loadSongs]`, `[RecapEntryViewModel.kt:today]`: Folder (`folder_playlist:`) and smart playlists guard against manual edits; MediaStore index builds under `mediaStoreIndexMutex`; stats song cache synchronizes via `loadSongsMutex`; recap entry re-evaluates date across midnight boundaries.

## Side Effects
- **Media Playback & Audio Routing**: `[PlayerViewModel.kt:mediaControllerFuture]`, `[PlaybackStateHolder.kt]`, `[MashupViewModel.kt]`, `[EqualizerViewModel.kt]`, `[AudioOutputStateHolder.kt]`, `[SleepTimerStateHolder.kt]`: Connect and command `MediaController` / `ExoPlayer` / `DeckController` / `EqualizerManager`, configure `AudioManager` volume and preferred audio devices, and send custom session commands.
- **Persistence, Room DB & Preferences**: `[SettingsViewModel.kt]`, `[LibraryStateHolder.kt]`, `[PlaylistViewModel.kt]`, `[ThemeStateHolder.kt]`, `[ColorSchemeProcessor.kt]`, `[SetupViewModel.kt]`, `[ExploreViewModel.kt]`, `[ListeningStatsTracker.kt]`, `[StatsViewModel.kt]`, `[AudioBookmarksViewModel.kt]`: Read and write Room DAOs (`AlbumArtThemeDao`, `MusicRepository`, `PlaybackStatsRepository`, `AudioBookmarkRepository`), `UserPreferencesRepository`, `ThemePreferencesRepository`, `PlaylistPreferencesRepository`, `EqualizerPreferencesRepository`, `TransitionRepository`, and `DataStore`.
- **Network, Sync & Background Work**: `[SyncManager]` triggers in `[MainViewModel.kt]`, `[SettingsViewModel.kt]`, `[SetupViewModel.kt]`, `[ArtistSettingsViewModel.kt]`; API/network calls in `[AccountsViewModel.kt]` (ListenBrainz polling/scrobbles, Navidrome/Jellyfin logout), `[ExploreViewModel.kt]`, `[CloudDownloadsViewModel.kt]`, `[SongInfoBottomSheetViewModel.kt]` (MusicBrainz/offline downloads), `[LyricsStateHolder.kt]` (remote lyrics), `[StatsViewModel.kt]` / `[RecapViewModel.kt]` (artist images), and `[UpdatesViewModel.kt]`.
- **Filesystem, MediaStore, Cache & System APIs**: `[FileExplorerStateHolder.kt]`, `[ExternalMediaStateHolder.kt]`, `[MetadataEditStateHolder.kt]`, `[BulkLyricsEmbedViewModel.kt]`, `[PlaylistViewModel.kt]`, `[StorageSenseViewModel.kt]`, `[DeviceCapabilitiesViewModel.kt]`, `[ConnectivityStateHolder.kt]`, `[SongInfoBottomSheetViewModel.kt]`: Query/write MediaStore and SAF URIs, cache/delete audio, cover art, `.lrc`, `.m3u`, and `.zip` files, register system `NetworkCallback`/`BroadcastReceiver`/`AudioDeviceCallback`, update `RingtoneManager`, update app shortcuts, and trigger `Toast` / `MaterialAlertDialogBuilder` / `IntentSender` permission prompts.
