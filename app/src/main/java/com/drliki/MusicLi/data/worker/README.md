# Worker

## Overview
Implements WorkManager background synchronization, cloud track downloads, bulk embedded-lyrics embedding, ListenBrainz scrobble flushing, and local library sync scheduling/planning under `com.drliki.MusicLi.data.worker`.

## Interface
- `[SyncWorker.kt:SyncWorker]` — `@HiltWorker CoroutineWorker` executing local MediaStore/tag scans, album/artist deduplication, Room persistence, LRC auto-scanning, orphaned artwork cleanup, and cloud sync (`doWork`, companion constants `WORK_NAME`, `PERIODIC_MAINTENANCE_WORK_NAME`, `INPUT_FORCE_METADATA`, `INPUT_RUN_MAINTENANCE`, `INPUT_SYNC_MODE`, `INPUT_BYPASS_PLAYBACK_DEFERRAL`, `TAG_PLAYBACK_DEFERRABLE`, `CURRENT_METADATA_CHARSET_REPAIR_VERSION`, `CURRENT_EMBEDDED_TAG_SCAN_VERSION`, `PROGRESS_*`, `OUTPUT_TOTAL_SONGS`, and builders `invalidateGenreCache`, `startUpSyncWork`, `incrementalSyncWork`, `fullSyncWork`, `rebuildDatabaseWork`, `periodicMaintenanceWork`), plus `[SyncWorker.kt:SyncMode]` and internal `shouldReadEmbeddedMetadata`, `withMusicBrainzIdsFallback`.
- `[SyncManager.kt:SyncManager]` — `@Singleton` lifecycle-aware sync coordinator (`isSyncing`, `syncFailed`, `syncProgress`, `isFetchingChanges`, `isPerformingMaintenance`, `start`, `sync`, `incrementalSync`, `fullSync`, `rebuildDatabase`, `forceRefresh`) plus `[SyncManager.kt:SyncProgress]` and `[SyncManager.kt:SyncProgress.SyncPhase]`.
- `[SyncExecutionPlan.kt:SyncExecutionPlan]`, `[SyncExecutionPlan.kt:LocalScanMode]`, `[SyncExecutionPlan.kt:FollowUpSyncDecision]`, `[SyncExecutionPlan.kt:buildSyncExecutionPlan]`, `[SyncExecutionPlan.kt:incrementalFetchTimestampSeconds]`, `[SyncExecutionPlan.kt:localFetchTimestampSeconds]`, `[SyncExecutionPlan.kt:shouldDeferSyncForPlayback]`, `[SyncExecutionPlan.kt:followUpSyncDecision]`, `[SyncExecutionPlan.kt:playbackDeferredSyncWorkIds]`, `[SyncExecutionPlan.kt:shouldRunForegroundCatchUp]` — Internal pure sync planning and deferral policies (`MAX_CONSECUTIVE_FOLLOW_UP_SYNCS = 5`).
- `[LocalLibraryChangeTracker.kt:LocalLibraryChangeTracker]` — `@Singleton` atomic change-version tracker (`onMediaStoreChanged`, `onLocalScanStarted`, `hasUnscannedChanges`, `consecutiveFollowUps`, `recordFollowUp`, `resetFollowUps`).
- `[AlbumGroupingUtils.kt:LocalAlbumIndex]`, `[AlbumGroupingUtils.kt:AlbumGroupingKey]`, `[AlbumGroupingUtils.kt:resolveAlbumArtist]`, `[AlbumGroupingUtils.kt:buildAlbumGroupingKey]`, `[AlbumGroupingUtils.kt:buildAlbumGroupingKeys]`, `[AlbumGroupingUtils.kt:buildTitleOnlyAlbumKey]`, `[AlbumGroupingUtils.kt:chooseAlbumDisplayArtist]`, `[AlbumGroupingUtils.kt:resolveAlbumDisplayArtistId]` — Internal album grouping and ID allocation helpers.
- `[ArtistParsingUtils.kt:collectArtistNames]`, `[ArtistParsingUtils.kt:choosePreferredArtistName]` — Internal multi-artist delimiter/title extraction and deduplication helpers.
- `[CloudSyncCoordinator.kt:CloudSyncCoordinator]` — `@Singleton` coordinator for Navidrome and Jellyfin unified library sync (`needsActiveCloudSync`, `syncUnifiedCloudLibraries`).
- `[CloudTrackDownloadWorker.kt:CloudTrackDownloadWorker]` — `@HiltWorker CoroutineWorker` for resumable/validated Navidrome and Jellyfin offline audio downloads (`doWork`, companion keys `KEY_*`, internal `extensionFor`).
- `[NavidromeSyncWorker.kt:NavidromeSyncWorker]` — `@HiltWorker CoroutineWorker` syncing Navidrome playlists/songs (`doWork`, `startAllSync`, `startPlaylistSync`).
- `[JellyfinSyncWorker.kt:JellyfinSyncWorker]` — `@HiltWorker CoroutineWorker` syncing Jellyfin playlists/songs (`doWork`, `startAllSync`).
- `[BulkLyricsEmbedWorker.kt:BulkLyricsEmbedWorker]` — `@HiltWorker CoroutineWorker` running foreground batch tag embedding via `BulkLyricsEmbedManager` (`doWork`).
- `[ScrobbleFlushWorker.kt:ScrobbleFlushWorker]` — `@HiltWorker CoroutineWorker` flushing pending ListenBrainz scrobbles in batches (`doWork`, `WORK_NAME`, `request`).

## Invariants
- `[SyncWorker.kt:SyncWorker.persistLocalScan]` serializes Room local scan commits under `localScanCommitMutex` and aborts (`Result.retry()`) if `getLocalAlbumGroupingSettings().indexVersion` changed mid-scan; sync markers (`setLastSyncTimestamp`, `markDirectoryRulesVersionApplied`, `clearArtistSettingsRescanRequired`, etc.) only update after a successful commit.
- `[SyncWorker.kt:SyncWorker.doWork]` requires `READ_MEDIA_AUDIO` (API >= 33) or `READ_EXTERNAL_STORAGE`, calls `localLibraryChangeTracker.onLocalScanStarted()` before querying `MediaStore`, and defers `INCREMENTAL` sync during active playback up to `MAX_PLAYBACK_DEFERRALS` (`5`); `[SyncWorker.kt:SyncWorker.fetchGenreMap]` returns empty on API >= 30 and caches for `1` hour.
- `[SyncWorker.kt:withMusicBrainzIdsFallback]` falls back across `(mbRecordingId, mbReleaseId, mbArtistId)` atomically so IDs from different matches are never mixed; `[SyncWorker.kt:SyncWorker.isSongUnchanged]` preserves user-edited metadata flags while repairing `\uFFFD` album-artist values when `metadataCharsetRepairPending` is true.
- `[SyncManager.kt:SyncManager]` skips startup incremental sync within `MIN_SYNC_INTERVAL_MS` (`6h`), enforces `FOREGROUND_SYNC_COOLDOWN_MS` (`60s`) unless MediaStore generations changed, requires `initialSetupDoneFlow == true` for auto/follow-up syncs, and caps consecutive follow-up syncs at `5` before backing off `30s`.
- `[AlbumGroupingUtils.kt:LocalAlbumIndex]` resolves lowest existing album ID per key, excludes unknown album titles from title-only grouping (`[AlbumGroupingUtils.kt:buildTitleOnlyAlbumKey]`), and generates collision-free fallback IDs; `[ArtistParsingUtils.kt:collectArtistNames]` keeps the first artist as primary.
- `[CloudTrackDownloadWorker.kt:CloudTrackDownloadWorker.doWork]` validates `KEY_DOWNLOAD_ID`/`KEY_ATTEMPT_ID`/`KEY_SOURCE_URI`, aborts if DB attempt/URI changed, enforces `CloudStreamSecurity` URL/MIME/size checks (`<= 2 GiB`) and non-empty exact `Content-Length` matches, wraps `COMPLETE` commits in `NonCancellable`, and retries `< 3` times on `IOException`/HTTP `>= 500`.
- `[ScrobbleFlushWorker.kt:ScrobbleFlushWorker.doWork]` stops without deleting on `AuthFailed`, processes up to `100` batches of `50` listens, and isolates `InvalidPayload` items individually.
- `[BulkLyricsEmbedWorker.kt:BulkLyricsEmbedWorker.doWork]` exits early unless `prepareResumeFromWorker()` succeeds and status is `RUNNING`, and requires `POST_NOTIFICATIONS` on API >= 33 for status notifications.

## Side Effects
- `[SyncWorker.kt:SyncWorker]` queries `MediaStore`, reads audio file metadata (`AudioMetadataReader`), mutates Room (`MusicDao`), updates `UserPreferencesRepository` and `LocalLibraryChangeTracker`, cleans orphaned album art cache files, scans `.lrc` files via `LyricsRepository`, triggers `CloudSyncCoordinator` and `ArtistImageRepository.clearCache()`, records `PerformanceMetrics`/`AdvancedPerformanceDiagnostics`, and reports `WorkManager` progress.
- `[SyncManager.kt:SyncManager]` observes `MediaStoreObserver` and `ProcessLifecycleOwner`, reads `MediaStore` generations, and enqueues/cancels `WorkManager` jobs (`WORK_NAME`, `PERIODIC_MAINTENANCE_WORK_NAME`).
- `[CloudSyncCoordinator.kt:CloudSyncCoordinator]`, `[NavidromeSyncWorker.kt:NavidromeSyncWorker]`, and `[JellyfinSyncWorker.kt:JellyfinSyncWorker]` invoke Navidrome/Jellyfin network syncs and update local Room caches.
- `[CloudTrackDownloadWorker.kt:CloudTrackDownloadWorker]` executes HTTP GETs via `OkHttpClient`, writes/deletes `.part` and audio files in `CloudOfflineRepository.downloadDirectory`, exports via `CloudDownloadExports`, updates `OfflineTrackDao`, and posts `CloudDownloadNotifications`.
- `[BulkLyricsEmbedWorker.kt:BulkLyricsEmbedWorker]` runs as a `FOREGROUND_SERVICE_TYPE_DATA_SYNC` foreground worker (`bulk_lyrics_embed` channel, IDs `8402`/`8403`) driving `BulkLyricsEmbedManager`.
- `[ScrobbleFlushWorker.kt:ScrobbleFlushWorker]` submits listens to ListenBrainz over HTTP, updates/deletes `ListenBrainzDao` rows, and schedules delayed flush work.
